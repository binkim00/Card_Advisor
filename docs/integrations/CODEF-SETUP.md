# CODEF 신청·발급 안내

2026-10-20 공식 홈페이지의 회원가입·멤버십·로그인 화면과 공식 Java SDK를 확인했다. 계정 생성/약관 동의/본인인증/이용 신청은 사용자가 직접 한다. 이번 안내만으로 실제 금융정보 전송을 활성화하지 않는다.

## 1. 회원가입
[CODEF 회원가입](https://codef.io/account)에서 필수 약관과 개인정보 내용을 확인하고 본인인증, 이름, 이메일 중복확인, 비밀번호 설정을 진행한다. 현재 공개 가입 화면에 회사정보란도 있다. 개인 개발자 자격/회사정보 입력 필요 여부가 계정에서 불명확하면 임의의 사업자정보를 넣지 말고 [서비스 문의](https://codef.io/contact/0)로 확인한다. 선택 마케팅 동의는 사용자가 결정한다.

## 2. 데모 신청
로그인한 뒤 [멤버십](https://codef.io/pricing/overview)의 **데모버전 → 시작하기**로 진행한다. 미로그인 상태에서는 로그인으로 이동하는 것을 확인했다.

현재 공식 안내는 샌드박스=테스트 데이터, 데모=실제 데이터로1개월간 하루100회 무료(일부 제휴 API 제외), 정식=별도 상담이다. 신청 화면에 표시되는 현재 기간·제약·승인 상태를 우선한다. 정식 상품의 사용량 제한 설명과 무료/무과금 여부를 혼동하지 않는다.

신청 용도 예시: “개인1인이 본인 명의 KB국민·하나카드의 보유카드/승인·취소 내역을 조회하여 수동 가계부와 결제 전 카드 추천을 검증하는 Android 개발 프로젝트. 자동 결제 없음.”

KB·하나 개인카드 보유카드/승인 조회의 데모 제공 여부, 허용 인증방식, 본인조회·재조회 허용 조건, 호출 한도 차감 기준, 추가인증 방식을 확인한다. 타인 테스트/공개 서비스는 별도 이용 조건 확인이 필요하다. 상품별 지원 여부를 가입만으로 확정하지 않는다.

## 3. 발급 정보 확인
데모 사용 가능 상태가 되면 계정의 API 키/클라이언트 정보에서 **데모 Client ID, Client Secret, RSA 공개키**를 확인한다. 공식 SDK는 `https://codef.io/#/account/keys`를 안내하지만 현재 홈페이지 개편으로 로그인 후 메뉴/경로가 다를 수 있다. 샌드박스·데모·정식 키를 섞지 않는다. 공개키는 RSA 암호화용 공개키이며 개인키가 아니다.

출처: [CODEF 공식 Java SDK](https://github.com/codef-io/easycodef-java#use-it). Access Token은 서버 코드에서 발급/재사용하므로 토큰을 수동으로 채팅에 보낼 필요가 없다. Connected ID는 금융 연결 요청 시 얻는 사용자별 식별자이며 Client ID와 다르다.

## 4. 프로젝트에 비밀값 저장
프로젝트의 `config/codef.example.properties`를 `.local/codef.properties`로 복사한다. 기존 파일이 있으면 덮어쓰지 않는다. `scripts/prepare-codef-config.ps1`은 빈 예시만 준비하고 현재 Windows 사용자와 SYSTEM으로 파일 접근을 제한한다. 키를 출력하지 않으며 외부 API를 호출하지 않는다.

로컬 편집기에서 clientId/clientSecret/publicKey를 채운다. 파일은 저장소에서 제외된다. `environment=DEMO`는 실제 데이터용이므로 계정의 데모 환경과 일치하는지 확인한다. **설정 준비 중에는 enabled=false, usageApproved=false를 유지한다.** 이용 조건 확인과 사용자의 실제 호출 결정 후에만 활성화한다. 기관 로그인 ID/PW는 이 파일에 저장하지 않고 보호된 앱 입력창에서만 직접 입력한다.

서버 실행 환경의 `CODEF_CONFIG_FILE`은 이 파일 절대 경로로, `CODEF_STORAGE_KEY_FILE`은 기존 `.local/finance-storage.properties`로 지정한다. `.env`에 해당 설정 경로가 이미 있는지 확인해 중복 줄을 만들지 않는다. 저장 키 파일은 Connected ID 암호화에 필요하므로 기존 키를 재생성/덮어쓰지 않는다.

## 5. 실제 연결 확인 시
키 설정만으로 실제 연결 성공이 아니다. 서버 재기동 후 로그인 상태에서 준비 상태를 확인하고, 앱의 금융 연결 관리에서 본인 동의와 기관 인증을 직접 수행한다. 연결 결과가 ACTIVE/SUCCEEDED인지, 이후 승인 내역·취소·중복이 맞는지 대조한다. 추가인증/UNKNOWN이면 성공으로 바꾸거나 자동 재시도하지 않는다.

채팅에는 **회원가입 여부, 데모 신청/승인 상태, 로컬 키 입력 완료 여부, 비밀값을 제거한 고정 오류코드**만 알려준다. Client Secret, RSA 키 내용, Connected ID, 카드사 비밀번호/OTP는 보내지 않는다.
