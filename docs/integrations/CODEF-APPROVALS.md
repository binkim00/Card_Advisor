# CODEF 승인 정규화·거래 동기화 계약

확인일: 2026-10-19. KB(0301)·하나(0313) 개인카드만 지원한다. 문서 계약과 합성 응답을 검증했고 2026-10-20 KB 실제 DEMO 연결·조회도 확인했다. 카드 혜택 실적 확정이나 운영 계약 검증을 의미하지 않는다.

## 공식 근거
- [개인 승인내역](https://developer.codef.io/products/card/common/p/approval): 이번에는 브라우저로 동적 본문을 확인했다. 개인 승인 경로, 단건 객체/다건 배열, 입력 옵션과 출력 필드를 확인했다.
- [카드 개요](https://developer.codef.io/products/card/overview): KB 0301, 하나 0313.
- 위 승인 페이지의 [공식 기관별 명세](https://docs.google.com/spreadsheets/d/1oXznKYr7FfIZilBLlAWseVF-5GZHx1di/edit#gid=1276479821): `승인내역` 및 `[참고] 승인내역 취소건` 시트를 내려받아 확인했다. 취소 시트의 표시 갱신일은 2026-05-07이며 실제 기관 응답과 달라질 수 있다는 주의가 있다.

이전 CODEF.md의 동적 본문 미확보 상태는 위 승인 문서·기관 코드·취소 시트에 한해 해소했다. 요금·계약·호출 제한, 실제 기관 인증 성공까지 확인한 것은 아니다.

## 정규화
| 공식 필드 | 내부 처리 |
|---|---|
| resUsedDate, resUsedTime, resApprovalNo, resCardNo | 날짜·시각·승인번호·마스킹 카드로 연결별 식별 지문 구성. 누락이면 보류. 카드번호는 앞4/뒤4 외 제거 |
| resUsedAmount, resAccountCurrency | KRW 정수만 원장 반영. 빈 값·소수 원·범위 초과는 보류. 외화는 원화금액을 임의 환산하지 않고 보류 |
| resCancelYN | 0 정상, 1 취소, 2 부분 취소, 3 거절. 거절은 구매를 만들지 않음 |
| resCancelAmount | 양수 승인에 포함된 누적 취소 금액. 공백을0으로 바꾸지 않음. 이전 취소보다 증가한 차액만 반영 |
| KB 음수 resUsedAmount + 빈 resCancelAmount | 취소전표매입 Type 2 별도 취소. 원거래 연결을 추측하지 않고 사용자 확인 전 보류 |
| resPaymentType, resInstallmentMonth | 일시불1/할부2/기타3 구분. 할부는 승인 총액 한 번과 개월 수를 저장. 월 청구액·수수료·혜택 실적 배분은 추정하지 않음 |
| resKRWAmt, resPaymentDueDate | 외화 취소 환율·월별 청구 지출로 임의 변환하지 않음 |
| 주소·전화·commSession 등 | 정규화/DB/로그/AI 요청에 저장·전달하지 않음 |

KB·하나의 공식 취소 표는 부분 취소 구분을 보장하지 않는다. 수치가 제공된 경우의 계산 검사를 통과했다는 뜻이며 실제 모든 부분 취소를 찾는다는 보장이 아니다. `resPaymentType=3`에는 KB 선할인 할부가 포함될 수 있어 일시불로 바꾸지 않는다. 정상 상태0인 행에만 취소0이 명시적으로 성립한다.

Type 1은 한 행의 승인액과 누적 취소액, Type 2는 별도 취소 행이다. 두 방식이 같은 원거래에 섞이면 기존 반영 이력으로 이중 차감을 막고 보류한다. 취소 감소, 승인액 변경, 초과 환불도 기존 원장을 덮어쓰지 않는다. 같은 응답 안에서 동일 식별자의 내용이 다르면 전체 요청을 실패 처리한다.

정규화 버전: `CODEF_KB_HANA_20261020_MASK2`. 행 출처 `SYNTHETIC`은 테스트 전용 loopback 공급자, `PROVIDER_REPORTED`는 실제 공급자 보고다. 실제 카드 혜택 규칙 검증이나 공식 실적 확정을 뜻하지 않는다.

## 조회와 저장
`/v1/kr/card/p/account/approval-list`에 연결의 암호화 Connected ID를 복호화해서 요청한다. 문서에 있는 `inquiryType=1`, `orderBy=1`, `memberStoreInfoType=0`을 사용한다. 임의 페이지/커서 필드를 만들지 않는다. 문서의 승인 API에는 별도 페이지 규약이 없으므로 한 번의 명시적 기간 조회만 처리한다.

한 요청은 최대31일이며 자동 기간 분할·주기적 폴링은 없다. 이는 앱의 안전한 처리 단위이지 CODEF 이용 한도가 아니다. 문서의 KB 최근12개월, 하나 최근18개월을 넘는 요청은 차단한다. 하나의3개월 단위보다 짧게 조회한다. 빈 배열은 기존 거래를 삭제하는 근거가 아니다. IMPORTED는 요청한 응답의 처리 결과이며 전체 금융 이력의 완전성을 보증하지 않는다.

네트워크 호출 전에 RUNNING 작업을 커밋한다. 같은 사용자/키/본문은 재전송하지 않으며 다른 본문은409다. 연결당 동시 조회1개, 사용자 행 잠금과 DB 유일키로 원장 반영을 직렬화한다. 조회 중 해제·재인증 등 연결 버전이 바뀌면 전체 반영을 거절한다. 중단된 RUNNING은10분 후 다음 명시적 요청에서 FAILED로 정리하며 자동 외부 재시도는 없다.

연결별 HMAC 키 ID를 최초 조회 때 고정해 키 교체 뒤에도 거래 식별이 유지되게 했다. 이 키는 거래가 남은 동안 삭제하면 안 된다. 원문 승인번호·전체 카드번호·응답 전체는 DB에 남기지 않는다. 거래 금액·날짜·마스킹 카드·출처와 상태만 보존한다.

KRW 승인 총액은 구매일의 예산 지출로 기록한다. 이는 주문 가치나 포인트·머니 포함 결제 합계가 아니라 `카드 승인액 기준`이다. 미확인 주문 금액을 생성하지 않는다. 은행 출금·카드대금·청구내역 API를 호출하지 않으므로 카드대금 출금을 새 지출로 넣지 않는다.

금융 원장은 `source=CODEF`, 카테고리 OTHER로 생성된다. 카드 상품 매핑/혜택 규칙은 미검증이므로 카드 실적·혜택 자격에 가상 규칙을 적용하지 않는다. 수동 원장과 명시적으로 연결한 경우에도 가상 규칙 스냅샷은 제거한다. 카테고리·예산 포함 편집은 보존한다.

같은 날짜/총액의 수동 기록은 중복 후보로 보류한다. 사용자 확인으로 기존 원장 연결 또는 별도 구매를 선택해야 한다. 금융 관리 대상 원장에 수동 취소·가상 카드 연결을 추가해 이중 반영하는 것은409로 차단한다.

새 증거/변경/반영/확인은 사용자 데이터 버전을 올려 이전 추천을 무효화한다. 미해결 거래가 있으면 추천 생성은409 FINANCIAL_REVIEW_REQUIRED로 보류하고 예산 요약은 pendingFinancialTransactions를 포함한다. 미확인 환불을0으로 확정하지 않는다.

## 자체 API
앱 Bearer 인증이 필요하다. Connected ID/원문 금융 응답을 클라이언트에서 받지 않는다.

| API | 요청/결과 |
|---|---|
| POST /v1/finance/connections/{id}/sync | Idempotency-Key(UUID), from/to(YYYY-MM-DD), expectedVersion. RUNNING/IMPORTED/PARTIAL/FAILED와 received/applied/held 반환 |
| GET /v1/finance/sync-runs/{id} | 본인 실행 상태/오류 코드 |
| GET /v1/finance/connections/{id}/transactions | 본인 정규화 거래, 할부 정보, 출처, version, 보류 이유·원장 연결 |
| POST /v1/finance/transactions/{id}/resolve | version + action. LINK_MANUAL(ledgerId), IMPORT_SEPARATELY, LINK_CANCELLATION(approvalId), IGNORE |

IGNORE는 아직 원장이나 원거래에 연결하지 않은 보류 건만 가능하다. 반영한 거래의 미확인 후속 증거를 무시해 추천을 재개할 수 없다. 별도 취소 연결은 같은 사용자/연결/마스킹 카드의 반영된 원거래만 받는다. 승인번호만으로 자동 연결하지 않는다.

HTTP200만으로 동기화 성공을 판단하지 말고 status를 확인한다. FAILED/보류의 오류는 고정 코드이며 원문 공급자 메시지를 전달하지 않는다. 과도한 기간/지원하지 않는 기관422, 타 사용자404, 키·버전·상태 충돌409, 비활성503이다.

## 실행·남은 사항
PostgreSQL이 실행 중이면 `./scripts/backend.ps1 sync-test`로 합성 응답→실제 Spring HTTP→PostgreSQL 검사를 실행한다. 실금융 자격증명은 필요 없다.

Android의 동기화 실행·보류 거래 확인 화면은 연결하고 합성 응답으로 검증했다. 신규 물리 기기는 아직 검증하지 않았다. 실제 KB/하나 인증, 추가 인증 이어하기, 보유 카드와 실제 상품 매핑, 외화 환불·할부 청구 배분, 불완전 기관 응답의 대조는 남아 있다. 기존 로컬 CODEF 설정은 꺼둔 상태다. 사용자의 키·카드번호·비밀번호를 채팅에 받지 않는다. 실제 연결 준비는 CODEF.md의 로컬 설정 절차를 따른다.

Android 동기화 진입: 설정 → 금융 연결 관리 → 연결별 기간별 거래·보류 확인. 저장된 결과 조회는 외부 재호출하지 않는다. 최근 작업20개는 `GET /v1/finance/connections/{id}/sync-runs`로 조회한다. 상세 [Android 동기화 검증](../verification/2026-10-19-android-sync.md).

## KB 실제 마스킹 형식 추가(2026-10-20)
공식 공통 문서의 resCardNo 예시는 앞4/뒤4 형식이지만 실제 KB33건은 앞13자리 별표/뒤3자리 형식이었다. 원문 없이 형식별 건수로 대조했다. KB0301에서만 해당 형식을 추가 허용하고 마스킹을 그대로 보존한다. 알 수 없는 앞자리나 숫자를 생성하지 않는다. 날짜·시각·승인번호·연결별 HMAC 식별을 함께 사용한다.
기존 MISSING_IDENTITY/HELD/구버전이며 원장·취소 연결이 없는 행만 이전 정규화 지문과 정확히 대조해 동일 UUID에 새 식별을 적용한다. 이전 지문 후보 충돌 시 요청 전체를 보류하고 추측 병합하지 않는다. 실제33행이 유지되고32건 가계부 반영, 원거래 연결 필요 취소1건 보류를 확인했다.
