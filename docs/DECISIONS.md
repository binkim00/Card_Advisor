## 2026-10-16: 카드 연결과 월별 실적

## 2026-10-19: 연결 거래 혜택 사용액과 잔여 한도
- 월별 DB remaining_cap_won 및 PUT remainingCapWon은 연결 거래를 차감하기 전 기준 한도다. GET performance는 이를 baseRemainingCapWon으로 노출하고 remainingCapWon은 거래 반영 후 계산값이다. Android 월별 저장은 기준 한도를 보존해 이중 차감을 막는다.
- ledgerBenefitUsedWon은 연결 거래의 사용액이다. 미기록 거래의 혜택 사용액이나 상품 전체 월 한도가 확인되지 않았으므로 이를 월 전체 사용액으로 주장하지 않는다. 기준 한도는 미기록 거래 반영 후, 연결 거래 반영 전의 가상 입력값이다.
- SYNTHETIC_BENEFIT_V1: 건별 (카드 승인액−카드 환불액)×비율을 정수 원 절삭한 뒤 월별 합산, 기준 한도 이내로 제한한다. currentQualified가 false면 사용액0, 양수 거래의 자격·환불·규칙·한도가 미확인이면 확정하지 않는다. 실적 인정 여부/예산 포함 여부와 혜택 계산은 독립적이다.
- 부분/전체 취소와 카드 재연결 시 원구매 월 전체를 재계산한다. 한도 초과 소비가 남아 있으면 취소해도 한도가 복원되지 않을 수 있다. 실제 카드사의 선착순 배분·취소월·환급 정책으로 확정한 것이 아니다. 월별 자격 수정도 해당 월 전체 가상 추정에 반영한다.
- 거래 생성/카드 재연결 때 혜택 비율과 규칙 버전을 저장한다. V5는 생성 전용 가상 카드와 검증된 기존 가상 거래 연결에 한해 이를 보충하며 미연결 거래는 추정하지 않는다. V6는 변경 전 기준 한도로 생성한 기존 추천을 사용자 데이터 버전 갱신으로 무효화한다. 적용 완료 마이그레이션은 수정하지 않았다.
- 계산값은 저장된 거래·취소·기준값에서 조회 시 결정적으로 산출한다. 별도의 가변 누계 컬럼을 두지 않아 중복 요청·부분 취소에서 누계 불일치를 피한다. 구매/취소/상태 변경은 기존 사용자 행 잠금과 버전 관리로 직렬화된다.

- V7에 분류 전용 classification_version, 최종 수정 시각, 원래 생성 분류/포함 여부를 추가했다. 분류 충돌만409로 처리하며 취소/카드 연결은 서로 다른 필드를 갱신한다. 사용자 행 잠금으로 예산·추천 조회와 수정은 일관된 상태를 읽는다.

- 화면의 값은 수동 입력이며 금융기관의 업종 코드나 실제 카드 혜택 분류를 수정한 것이 아니다.

## 2026-10-19: 반복 고정비와 거래 연결
- 기존 수동 fixedRemainingWon과 반복 일정 잔액을 합산하면 이중 예약이 된다. 월별 Budget.fixedCostMode를 MANUAL/SCHEDULED로 명시적으로 선택한다. 기존/생략 요청은 MANUAL 또는 기존 기준을 유지하고 수동값을 지우지 않는다. 예산이 없는 월은 적용 잔액null이다.
- 월별 발생건은 일정 ID+월로 식별한다. 매월 별도 배치로 복제하지 않고 V8의 적용 월별 규칙과 해당 월 연결 거래에서 조회 시 생성한다. 월말 보정(예정일31→2월말), 변경 전 월 보존, 이미 지정한 이후 월 변경 보존을 지원한다. 원문 occurrence ID 경로는 일정ID/월 경로로 정규화했다. 별도 알림/자동결제/자동 매칭은 추가하지 않았다.
- active 잔여=max(예상액−예산에 포함된 연결 거래 순지출,0). inactive는0. 예상액보다 실제 금액이 적으면 차액은 계속 예약하며 추가 지출이 없으면 사용자가 예상액을 수정한다. 과납은 예약액을 음수로 만들지 않는다. 부분/전체 취소와 예산 제외는 해당 순지출만큼 예약을 복원한다. 원래 구매 월에 귀속하는 현 가계부 취소 정책을 따른다.
- 연결은 사용자 확인에 의해서만 수행한다. 같은 사용자·같은 구매 월로 제한하고 거래 하나는 일정 하나에만 연결한다. 분할 납부는 여러 거래를 한 일정에 연결한다. 다른 월 청구/납부의 배분, 거래 일부 금액 배분, 자동 매칭 후보는 미구현이다.

- 새 공급자 조회와 저장 결과 조회를 구분한다. 연결별 최근20개 작업 조회 API로 응답 유실·재로그인 때 결과를 복구하며 자동 재전송/주기적 폴링하지 않는다. RUNNING이면 새 요청을 보류한다.
- 응답 전체 검증 뒤 UI에 반영한다. 버전 충돌은 선택을 보존하지만 재조회 전 변경을 막는다. 재조회는 기존 선택을 제거해 새 버전의 후보를 명시적으로 재확인한다.
- 같은 날짜/금액은 중복 후보일 뿐이다. 기존 구매 연결·별도 구매 추가·취소 원거래를 사용자에게 구별해 보여주고 최종 확인으로 저장한다. 분류/예산 포함은 보존하며 가상 실적/혜택 제거를 안내한다.
- 실제 공급자 호출 여부와 DB 반영 상태를 분리한다. SYNTHETIC은 화면에 명시하며 미확인 환불은0으로 표시하지 않는다. 보류 금융 증거가 있으면 예산에 안내하고 추천을 보류한다.
- 시험은 test 소스의 로컬 공급자/장애 주입만 사용한다. 화면 캡처나 원문 실패 로그 대신 고정 단계·예외 종류·소스 위치·합성 금액/DB 대조만 보존한다.

## 금융 카드 상품 연결 경계(2026-10-20)
- 부분 마스킹+공급자 표시 이름을 연결별 조회 그룹으로 제시하며 이름이나 끝자리로 상품을 자동 확정하지 않는다. 사용자 확인·동일 카드사·본인 등록 실제 상품만 연결한다. 부분 번호 충돌 가능성을 고지한다.
- V19 관계만 저장하고 기존 금융/원장/card_id/취소 금액은 변경하지 않는다. 연결 전 버전+기관 연결 버전으로 충돌을 막고 해제에도 버전을 유지한다.
- 매핑은 계산 조건 검수가 아니다. 연결된 월의 미검수 금융 거래가 있으면 해당 실제 카드의 실적/혜택은 미확인으로 표시하고 새 추천은 보류한다. 현재 혜택 자격과 다음달 실적은 분리한다. 거래별 제외/혜택 룰 연결은 후속 범위다.


## Android 로그인 유지(2026-10-20)
비밀번호 대신 access/refresh 쌍만 Android Keystore AES/GCM과 noBackup AtomicFile에 저장한다. AuthFilter의 SESSION_EXPIRED 확인 시 갱신을 한 번만 직렬화해 처리한다. 네트워크 오류만으로 로그아웃하지 않고 서버폐기/로그아웃/계정삭제는 저장값을 제거한다. 기존 서버 세션 유효기간은 유지한다.



## 실제 금융 거래 실적 확인 (2026-10-20)
- V20 side tables store per-owner approval decision, mapping/rule version, fingerprint, refund signature and per-cancellation issuer receipt date. Original financial/ledger/cancellation rows are not rewritten.
- INCLUDE/EXCLUDE/UNKNOWN is explicit user confirmation, not merchant-name inference or AI. Changed evidence/mapping invalidates the confirmation; identical replay does not change user revision. Existing benefits remain separately blocked until benefit-rule review.
- KB official Easy all terms: previous-month approval-date full installment amount; cancellation deducted in issuer slip receipt month. Source: https://card.kbcard.com/CRD/DVIEW/HCAMCXPRICAC0076?cooperationcode=09256&mainCC=a . User enters receipt dates; import timestamps never substitute. Unknown dates keep complete totals null while confirmed subtotal is separate.
- Unlinked cancellation and unverified non-KB refund policy remain unknown; Hana GO official PDF receipt policy could not be verified in this milestone. No-threshold Travelog remains product no-threshold, not inferred monetary evidence.
- Financial contribution replaces legacy matched manual calculation to prevent double count. Budget inclusion/category are independent. Current qualification remains a separate previous-period snapshot, and untracked baseline must be explicit for next-month total.
- Android secure editor supports read/save/readback, visible pending/error state, stale input preserved on conflict and explicit reload. No automatic mutation retry. No private screenshots/logs or provider credentials.
