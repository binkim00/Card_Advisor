# 03. 실적·혜택·예산 계산 및 추천 알고리즘

**상태: 구현 전 설계 제안 v1.0.** 수치 목표·기술 선택은 제안값이며 실측 또는 외부 승인 결과가 아니다.
## 1. 공통 입력과 신뢰 상태
CheckoutContext: 주문 경로, 결제 시각, 주문가치, 포인트·머니·카드 승인 예정액, 할부개월, 결제 수단, 카테고리 배분, 분할 승인 여부, snapshotVersion.
CardContext: 정확한 상품 버전, 현재 혜택 자격 기준 기간, 이번 달 실적, 혜택 사용량, 해당 데이터 기준 시각과 출처.
모든 금액은 정수 원. 비율은 정수 basis points(1%=100bp), 곱셈 후 상품의 절사/반올림 규칙을 적용한다. 중간 단계 부동소수점 사용 금지.
값마다 source=OFFICIAL/ESTIMATED/MANUAL/UNKNOWN, asOf, ruleVersion을 가진다. UNKNOWN은 0이 아니다. 기관 조회값이라도 갱신 이전 거래가 빠질 수 있으므로 ‘최종 확정 혜택’으로 부르지 않는다.
## 2. 주문액과 예산 지출액
- orderValueWon: 상품·배송비에서 쿠폰/즉시가격할인을 차감한 주문 가치.
- pointUsedWon: 구매 시 사용한 무상 적립포인트. 초기 예산 정책에서 현금 지출로 제외한다.
- prepaidMoneyUsedWon: 사전에 유상 충전한 머니의 사용액. 충전 시 자산 이동, 구매 시 지출로 처리한다.
- cardChargeWon: 이번 구매에서 카드에 승인될 예정액.
- 초기 P0 지원식: orderValueWon = pointUsedWon + prepaidMoneyUsedWon + cardChargeWon. 기타 수단 혼합은 확인 대상으로 보류한다.
- budgetExpenseWon = cardChargeWon + prepaidMoneyUsedWon. 카드사 청구할인·미래 적립은 현재 예산 지출에서 선차감하지 않는다. 이미 화면 가격에 반영된 즉시 할인은 다시 차감하지 않는다.
- 머니 충전 거래와 사용 거래를 구분할 근거가 없으면 둘 다 자동 지출로 넣지 말고 조정 필요 상태로 표시한다. 현금/구매포인트 구분 불가 시 정책 미확정 경고.
## 3. 예산 산식
monthSpend = 해당 월 구매 기준 지출 − 해당 원구매에 연결된 확정 취소·환불액. 이전 월 구매의 취소는 원구매 월을 재계산하고 이번 달 현금 유입은 별도 표시한다.
overallAfter = 월 전체 예산 − monthSpend − 이번 budgetExpense.<br>categoryAfter[k] = 해당 카테고리 예산 − 해당 소비 − 이번 배분액[k].<br>availableAfter = overallAfter − 아직 실거래와 매칭되지 않은 잔여 고정비.
여러 카테고리가 섞이면 사용자가 배분하고 합계가 budgetExpense와 일치해야 한다. 배분을 모르면 전체 예산만 확정 계산, 카테고리 예산은 ‘계산 보류’로 표시한다.
추천 조회만으로 지출·고정비·실적·혜택 한도를 변경하지 않는다. 모든 추천은 그 시점의 단일 구매 가정이며 다른 미결제 추천과 합산하지 않는다.
## 4. 카드 실적
performanceAfter[i] = currentPerformance[i] + eligiblePerformanceIncrement[i].
실적 증가액은 승인 예정액을 그대로 쓰지 않고 상품의 제외 항목·할부·할인 거래·간편결제·승인/매입일 기준을 적용한다.
현재 혜택 자격은 requiredPeriod의 검증된 실적으로 판단한다. 이번 구매로 다음 달 기준을 넘더라도 이번 결제의 혜택 등급을 올리지 않는다. 신규 발급 유예·가족 합산·카드 합산은 공식 규칙이 등록된 상품에만 적용한다.
목표 구간은 사용자 선택 또는 검증된 다음 유효 구간. gapBefore=max(0,target−current), gapAfter=max(0,target−after). 실적 제외 여부 불명은 gapAfter도 조건부다.
카드사 조회값과 자체 추정값은 섞어 합산하지 않는다. 공식 합계에 어떤 거래까지 포함됐는지 확인할 수 없으면 별도의 병렬 값으로 표시한다.
## 5. 혜택 엔진
1. 결제 시각에 유효한 상품·규칙 버전을 선택한다.
2. 현재 혜택 자격, 가맹점/업종, 결제 경로, 최소 승인액, 할부, 실적·혜택 제외 항목을 각각 평가한다.
3. rate/fixed/point 규칙으로 계산한 뒤 건별·일별·월별·공유 한도를 적용한다. 여러 규칙의 중복 허용/우선순위는 규칙에 명시한다.
4. 포인트는 공식 또는 사용자가 확인한 환산비율이 있을 때만 원화 비교. 환산 불명 포인트는 별도 단위로 표시하고 현금 순위에 임의 합산하지 않는다.
5. 분할 승인 예상인데 건별 금액을 모르면 건별 최소액·횟수 한도 적용 불가. 해당 혜택을 조건부로 표시한다. 주문 합계를 하나의 승인으로 가정하지 않는다.
6. 최종 카드 변경으로 쇼핑몰 가격이나 쿠폰이 달라지면 기존 금액으로 비교하지 않는다. 새 주문 스냅샷을 확인한다.
단일 비중복 정률 규칙 예: benefit = min(정해진 반올림(amount×rateBp/10000), 건별 잔여 한도, 공유 월 잔여 한도). 복합 규칙은 모든 한도 그룹의 교집합을 적용한다. 한도 미확인 시 최대 가능액을 확정액처럼 표시하지 않는다.

추천 결과에는 reasonCodes, appliedRuleIds, excludedReasons, opportunityCostWon, qualificationBefore/After, budgetImpact, uncertaintyReasons, expiresAt를 포함한다.

## 8. 계산 버전·검증
동일 ledgerRevision·budgetVersion·rulesetVersion·snapshotVersion이면 동일 결과를 반환한다. 월 경계, 규칙 개정, 취소 발생 때 영향 기간만 재계산한다. 추천 이력은 설명에 필요한 최소 스냅샷만 보존하며 현재 계산으로 과거 결과를 덮어쓰지 않는다.
