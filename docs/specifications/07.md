## 1. 외부 사실과 미확인 사항
CODEF 공식 SDK는 사용자별 Connected ID로 연결 기관의 데이터를 요청하는 구조와 계정 등록·추가·수정·삭제를 설명한다. 이 기술 구조만으로 데모·상용 이용 허용을 판단하지 않는다. [공식 SDK](https://github.com/codef-io/easycodef-node/blob/master/README.md)
이번 확인에서 멤버십·FAQ·API 상세 페이지의 동적 본문을 읽지 못했다. 데모 기간·호출 수·실적 API 지원·자동조회 조건은 **미확인**이다. 원문의 ‘1개월/하루100회’는 예산·일정·호출 정책의 확정 입력으로 사용하지 않는다.
1인 개발로 바뀌었으므로 우선 본인 1인 실데이터 조회 조건을 확인한다. 다른 테스터 추가는 별도 검토한다. 아직 공급자 문의를 보내지 않았다.

## 3. 인증·연결 흐름
사용자 앱 로그인 → 기관 선택/목적별 동의 → 서버 connectionSession 생성 → 해당 기관이 지원하는 인증 전달 방식 실행 → 기관별 결과 저장 → 사용자 소유 financialConnection 생성 → 첫 조회 작업.
Connected ID는 서버에서 암호화 보관하며 클라이언트가 임의 지정할 수 없다. 인증수단 암호화와 CODEF 통신 방식은 선택 API의 공식 규격을 구현한다. 단순히 ‘OAuth 로그인만 있으면 금융 연결 가능’으로 설계하지 않는다.
추가 인증이 필요하면 AUTH_REQUIRED로 멈춘다. 인증 실패는 조회 성공으로 취급하지 않는다. 계정 생성의 네트워크 시간초과는 외부에 실제 생성됐는지 확인한 뒤 재시도하여 중복 연결을 방지한다.
## 4. ProviderAdapter 계약
connect / continueAuth / listInstruments / fetchTransactions / fetchPerformance(지원 시) / fetchBenefitUsage(지원 시) / disconnect.
반환 공통: provider, institution, requestReference, retrievedAt, coverageFrom/To, hasMore, nextCursor, completeness, normalizedEvents, unsupportedFields.
원문 필드를 내부 normalized 모델에 매핑하는 표는 기관별로 작성한다. 숫자 문자열·원화기호·빈값·음수 취소 표현을 정규화하되 원본 의미를 잃으면 검토 상태로 보낸다. 외화 거래는 P0에서 조회 표시만 하고 원화 추천/예산 확정 계산에서 제외한다.
## 5. 동기화 처리
1. 로그인 사용자와 연결 소유권·동의·할당량을 확인한다.
2. 사용자+기관 단위 중복 작업을 묶고 허용된 기간을 요청한다. 초기 조회 범위는 이전 달 시작~현재 제안값이며 공급자 제한과 현재 자격 기간에 맞게 분할한다.
3. 각 페이지·기관의 성공 범위와 cursor를 기록한다. 일부 실패를 전체 성공으로 저장하지 않는다.
4. provider event ID가 있으면 이를 사용해 upsert. 없으면 기관·계좌/카드 식별·원승인번호·일시·금액·유형 조합을 비교하고 충돌은 후보로 남긴다.
5. 승인/매입의 동일 거래 여부를 식별자로 확인한다. 같으면 원거래의 상태 업데이트, 다른 이벤트를 새 구매로 더하지 않는다.
6. 취소·환불 연결 → 분류·이체·카드대금 검토 → 예산·실적·한도 projection 재계산 → ledgerRevision 일괄 교체.
7. 해당 사용자의 기존 추천을 무효화하고 기준 시각을 갱신한다.
기본 제안: 자동 반복조회 OFF, 사용자 명시적 새로고침만. 이후 허용된 환경에서만 최근 7일 겹침 재조회, 월초 이전 달 재확인 등 재조정 정책을 설정한다. 겹침 기간은 늦게 도착하는 취소를 전부 보장하지 않으므로 사용자가 기간 재조회를 요청할 수 있어야 한다.
## 6. 재시도와 제한
초기 제안: 같은 사용자·기관 새로고침 최소10분 간격. 실제 제한이 더 엄격하면 공급자 규칙 우선. 네트워크/일시 장애만 최대3회, 1분→5분→15분+작은 지터. 요청이 처리됐는지 불명확한 인증 생성·삭제는 무작정 재실행하지 않는다.
자격증명 오류·동의 철회·추가 인증은 자동 재시도 금지. 429는 공급자 재시도 시각을 따른다. 화면 변경 이벤트는 CODEF 호출로 이어지지 않는다. 한도 값이 확인되지 않으면 예약 수집을 켜지 않는다.

## 8. 동기화 완료 정의
요청 기간·기관별 페이지를 모두 처리하고 거래 재처리 시 합계가 동일하며, 원장과 projection revision이 같아야 SUCCEEDED다. ‘API 응답 성공’과 ‘취소/분류/실적 계산 완료’는 별도 지표다. 공식 실적·자체 실적이 다르면 차이와 기준일을 보여주고 한 값을 임의 조정하지 않는다.
