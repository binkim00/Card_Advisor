# 01. 제품 범위·기능 요구사항

<mention-page url="https://app.notion.com/p/3fbd86006d0281d9b3d0f2a734dd2d4a?pvs=204"/>
**상태: 구현 전 설계 제안 v1.0.** 수치 목표·기술 선택은 제안값이며 실측 또는 외부 승인 결과가 아니다.
## 제품 목표
이미 예정된 구매를 어느 보유 카드로 결제할지 판단하도록 돕는다. 구매 금액을 늘리거나 신규 카드 발급을 유도하지 않는다. 첫 사용자는 개발자 본인이며, 이후 다른 사용자를 추가할 경우 별도 동의·이용 조건·사용자 격리 검증을 거친다.
## 범위
- P0: 수동 입력, 카드 3종, 예산·고정비, 결정적 추천, 본인 금융 연결과 가계부, 한 쇼핑몰 주문 경로 감지, 오류·삭제 처리.
- P1: 무신사 또는 네이버의 두 번째 경로, AI 분류·설명·월간 분석. 원문 요구사항으로 유지하되 핵심 MVP 뒤에 구현한다.
- P2: 카드 4~5종, 추가 경로, 사용자 요청형 스크린샷 OCR. 일정 부족 시 생략할 확장 범위다.
- 제외: 결제 대행·자동 클릭·자동 카드 선택·임의 화면 수집·전 쇼핑몰 지원·카드 조건 무검수 자동 수집·미래 혜택 보장·가족 금융정보 연결.

## 비기능 목표
- 계산 정확성: 검증된 카드 규칙의 골든 사례 100% 일치. 알 수 없는 조건은 계산 실패 또는 조건부 결과로 반환한다.
- 응답: 카드 5개·검증 규칙 100개·단일 서버의 제안 시험 환경에서 추천 API p95 500ms 이하, 단말 감지 안정화 후 표시 p95 2초 이하 목표. CODEF와 AI는 추천 동기 경로에 넣지 않는다.
- 금액은 정수 원, 시각은 UTC 저장·Asia/Seoul 월 경계 적용. 카드사 자체 기간이 다르면 상품 규칙으로 명시한다.
- 목표 OS 범위는 보유 기기와 출시 시점 정책 확인 후 정한다. 현재 minSdk·targetSdk를 확정하지 않는다.
## 성공 지표와 해석
- ‘확정 가능한 결과’의 계산 오류 0건; 보류율은 별도 집계한다.
- 10개 실제 구매 예정 상황에서 8개 이상 사용자가 추천 이유와 즉시 혜택 차이를 설명할 수 있는지 탐색한다. 1인의 결과는 일반 사용자 만족도 근거로 확대하지 않는다.
- 감지된 정확한 금액 수/전체 주문 상태 수와 자동 추천 커버리지를 함께 기록한다. 보류로 정확도만 높이지 않는다.
## 범위 변경 기준
실제 카드 약관에서 필요한 규칙이 추가되면 04 → 03 → 05/06 → 11을 함께 갱신한다. 미검증 카드를 지원 카드 목록에 넣지 않는다. 1인 개발의 일정 압박은 P1/P2를 줄여 해결하고, 금액 정확성·소유권·삭제 처리는 줄이지 않는다.
