# 10. AI 분류·설명·분석 명세 및 평가

<mention-page url="https://app.notion.com/p/3fbd86006d0281d9b3d0f2a734dd2d4a?pvs=204"/>
**상태: 구현 전 설계 제안 v1.0.** 수치 목표·기술 선택은 제안값이며 실측 또는 외부 승인 결과가 아니다.
## 역할과 금지사항
AI는 소비 카테고리 제안, 검증된 추천 이유의 문장화, 기간별 지출 변화 설명, 예산 조정 초안을 만든다. 할인액·실적·예산·순위를 계산하거나 실제 결제를 수행하지 않는다. AI를 꺼도 카드 추천과 가계부 핵심 기능이 동작해야 한다.
## 처리 우선순위
사용자 정정 → 사용자 확인 가맹점 매핑 → 검증된 분류 규칙 → AI 제안 → 미분류. 사용자 정정은 다음 동기화·AI 실행에서 덮어쓰지 않는다. 현재 상점의 새로운 구매가 이전 카테고리와 다를 수 있으므로 가맹점 규칙은 수정 가능해야 한다.

원본 화면·배송지·연락처·계좌/카드번호·인증수단·Connected ID·거래 전체 목록을 보내지 않는다. 가맹점 토큰도 개인 생활정보를 드러낼 수 있으므로 최소화 및 별도 AI 동의가 필요하다. 외부 모델 제공자와 보존 설정은 아직 미정이며 실제 값 전송 전 확정한다.
## 분류 카테고리
쇼핑, 식비, 교통, 주거·통신, 구독, 의료·건강, 교육, 여가, 기타, 미분류. 이체·카드대금·취소 여부는 AI 분류가 아니라 원장 조정 규칙으로 결정한다.
confidence는 모델의 자기평가이며 정답 확률로 표시하지 않는다. 초기 제안: 0.85 이상도 ‘AI 제안’ 배지, 0.60~0.85는 확인 우선, 0.60 미만은 미분류. 기준은 평가 데이터에서 정밀도·커버리지를 보고 조정한다.
## 내부 계약 예시
```json
{
  "task": "EXPLAIN_RECOMMENDATION",
  "promptVersion": "exp-v1",
  "facts": [
    {"id": "f1", "type": "IMMEDIATE_BENEFIT_DIFFERENCE", "valueWon": 1000},
    {"id": "f2", "type": "TARGET_REACHED", "cardAlias": "B"},
    {"id": "f3", "type": "SHOPPING_BUDGET_AFTER", "valueWon": 20000}
  ],
  "constraints": ["NO_NEW_NUMBERS", "NO_GUARANTEED_FUTURE_BENEFIT", "NO_EXTRA_SPENDING_PROMPT"]
}
```
예상 문장: “B카드로 결제하면 입력한 실적 기준을 충족할 수 있습니다. 이번 혜택은 A카드보다 1,000원 적고, 구매 후 쇼핑 예산은 20,000원 남습니다.”
사실 검증에 실패하면 문장을 폐기하고 템플릿을 사용한다. 문구가 매끄럽더라도 원장/계산 결과와 다르면 채택하지 않는다.
## 모델·프롬프트 실행 제안
모델 제공자·제품 버전·요금은 선정 전. task+입력 해시+모델 버전+프롬프트 버전으로 캐시하고, 데이터 수정·동의 철회 시 관련 결과를 무효화한다.
추천 UI는 템플릿을 즉시 표시하고 AI 설명은 비동기로 대체한다. 초기 요청 제한 제안: 사용자 하루20회·작업별 입력/출력 상한 설정. 비용 한도가 정해지지 않으면 유료 모델 호출 기본 OFF. 타임아웃8초 후 템플릿 유지, 재시도1회 이내.
## 평가셋
합성/익명화한 분류 120건을 준비해 규칙 개발용80건과 별도 평가40건으로 분리한다. 각 카테고리 최소4건, 애매한 가맹점·환불·이체 유사 사례 포함. 동일 가맹점이 양쪽에 반복되어 성능이 부풀려지지 않도록 분할한다.
설명은 30개 사례: 기본/예산초과/실적제외/한도소진/미확인/미래자격 6종×5개. 개인정보 포함 문자열·지시문이 섞인 가맹점·허위 금액을 유도하는 사례를 추가한다.

점수는 소규모 시제품의 제안 목표이며 실제 성능이 아니다. 분류 평가와 설명 평가를 합산한 단일 정확도로 보고하지 않는다.
## 예산 변경의 제한
‘줄일 수 있음’ 제안은 사용자가 정한 목표 안에서만 제공한다. 필수 지출인지 모르는 의료·주거 지출을 단정적으로 줄이라고 하지 않는다. 추천 결과를 자동으로 저장 예산에 적용하지 않고 변경 전/후, 총액, 영향 카테고리를 확인시킨다.
