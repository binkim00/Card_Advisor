# 04. 카드 상품·혜택 규칙 데이터 명세

<mention-page url="https://app.notion.com/p/3fbd86006d0281d9b3d0f2a734dd2d4a?pvs=204"/>
**상태: 구현 전 설계 제안 v1.0.** 수치 목표·기술 선택은 제안값이며 실측 또는 외부 승인 결과가 아니다.
## 카드 선정
실제 보유 카드 중 정확한 상품명을 확인한 3종을 먼저 선택한다. 네이버/무신사에서 사용 가능한 결제 경로, 온라인/간편결제 혜택, 실적 구간, 약관 확보 가능성을 평가한다. 특정 카드가 유리하다고 사전에 정하거나 신규 발급을 권하지 않는다.
3종 구성 제안: 단순 기본 할인형 1종, 온라인/간편결제 조건형 1종, 실적 구간·통합 한도가 있는 카드 1종. 실제 보유 카드가 다르면 그 카드의 복잡도에 맞춰 일정 조정.

## 규칙 예시 — 실제 상품 아님
```json
{
  "productId": "SYNTHETIC_A",
  "ruleVersion": 1,
  "sourceType": "SYNTHETIC",
  "benefit": {"type": "RATE", "rateBp": 300, "roundingMode": "FLOOR", "roundingUnitWon": 1},
  "qualification": {"period": "PREVIOUS_CALENDAR_MONTH", "minimumWon": 300000},
  "performance": {"dateBasis": "APPROVED_AT", "installmentPolicy": "FULL_AT_PURCHASE"},
  "capGroup": {"id": "SYNTHETIC_A_MONTHLY", "period": "MONTH", "limitWon": 10000},
  "paymentMethods": ["DIRECT_CARD", "NAVER_PAY_CARD"],
  "minimumChargeWon": 1,
  "stackingPolicy": "EXCLUSIVE",
  "reviewStatus": "TEST_ONLY"
}
```
실제 등록 문서에는 위 값 복사 대신 공식 출처와 근거 문단을 연결한다. 테스트용 규칙은 실사용 데이터 영역으로 발행하지 않는다.

## 변경·발행 절차
공식 문서 확인 → 초안 등록 → 원문과 필드 대조 → 계산 골든 사례 작성 → 전체 관련 사례 통과 → 활성 버전 발행. 규칙 변경은 영향을 받는 기존 추천을 만료시키고 원장의 해당 기간을 재계산한다.
오류 발견 시 상품을 PAUSED로 전환해 새 추천에서 제외하고 이전 정상 버전으로 되돌릴 수 있다. 이미 표시한 결과는 정정 안내 대상으로 기록한다. 적용 시작일을 모르는 새 혜택을 과거 거래에 소급 적용하지 않는다.
## 유지관리
초기 제안: 활성 상품은 월 1회 원문 확인 및 사용자 오류 제보 때 수시 확인. 확인일은 유효기간의 대용값이 아니다. 기간성 프로모션은 P0 제외이며 넣을 경우 시작/종료·응모·예산 소진·대상자 조건까지 확인한다. 플랫폼 자체 적립과 카드사 혜택을 별도 출처로 관리하여 이중 합산을 막는다.
## 완료 산출물
실제 카드 3개의 출처·버전·필드 누락 검사·골든 테스트 결과·지원하지 않는 조건 목록. 현재 실제 카드가 지정되지 않았으므로 이 산출물은 **미작성·검증 전** 상태다.
