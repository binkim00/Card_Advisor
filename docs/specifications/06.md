# 06. API·오류·동시성 계약

<mention-page url="https://app.notion.com/p/3fbd86006d0281d9b3d0f2a734dd2d4a?pvs=204"/>
**상태: 구현 전 설계 제안 v1.0.** 수치 목표·기술 선택은 제안값이며 실측 또는 외부 승인 결과가 아니다.
## 공통 규칙
자체 백엔드의 제안 REST API이며 CODEF의 실제 API 경로가 아니다. prefix=/v1. 인증은 앱 로그인 토큰. 요청 userId·connectedId를 신뢰하지 않고 토큰 subject에서 user_id를 정한다. 객체 조회는 항상 소유권 검사하며 타 사용자 객체는 404로 처리한다.
JSON camelCase, 금액 integer KRW, 시각 ISO-8601 UTC, 월 YYYY-MM. 쓰기 body에는 version 포함, 오래된 version은409. 주요 생성·동기화·삭제에는 Idempotency-Key를 사용한다. 응답은 requestId를 포함하고 에러에 비밀/공급자 원문을 포함하지 않는다.
리스트: limit 기본20/최대100, cursor, nextCursor, hasMore. 생성201, 비동기 접수202, 성공200, 본문 없는 삭제204.

## CheckoutContext 스키마
필수: source(MANUAL/ACCESSIBILITY), merchantContext(NAVER_ORDER/MUSINSA_ORDER/OTHER), currency=KRW, orderValueWon, pointUsedWon, prepaidMoneyUsedWon, cardChargeWon, paymentMethod, installments(일시불=1), splitApproval(YES/NO/UNKNOWN), confirmedByUser, capturedAt, categoryAllocations.
감지 source에는 adapterVersion과 실제 지원 경로 ID 필수. categoryAllocations는 categoryId와 amountWon 배열이며 비어 있으면 카테고리 계산 보류. 자격·실적·금액·추천 카드 같은 계산 결과를 클라이언트에서 받지 않는다.
contextHash는 서버에서 금액·수단·할부·경로·카테고리·분할 여부를 정규화해 생성한다. 추천은 사용자·해시·snapshotVersion과 묶인다.
## 추천 요청·응답 예시
가상 데이터이며 예시의 짧은 ID는 문서 설명용이다. 실제 API는 UUID를 사용한다.
```json
{
  "checkoutId": "checkout-example",
  "snapshotVersion": 3,
  "mode": "BALANCED",
  "maxOpportunityCostWon": 1000
}
```
```json
{
  "requestId": "req-example",
  "data": {
    "recommendationId": "rec-example",
    "status": "VALID",
    "recommendedCardId": "synthetic-b",
    "basis": {"snapshotVersion": 3, "ledgerRevision": 12, "budgetVersion": 2, "ruleVersions": ["A:1", "B:1"]},
    "budgetImpact": {"expenseWon": 50000, "overallAfterWon": 70000, "categoryAfterWon": 20000, "availableAfterWon": 40000},
    "candidates": [
      {"cardId": "synthetic-b", "benefitWon": 500, "performanceAfterWon": 320000, "gapAfterWon": 0, "opportunityCostWon": 1000, "reasonCodes": ["TARGET_REACHED", "WITHIN_USER_TOLERANCE"], "uncertaintyReasons": []},
      {"cardId": "synthetic-a", "benefitWon": 1500, "performanceAfterWon": 350000, "gapAfterWon": 0, "opportunityCostWon": 0, "reasonCodes": ["MAX_IMMEDIATE_BENEFIT"], "uncertaintyReasons": []}
    ],
    "disclaimerCodes": ["ESTIMATE_NOT_SETTLED", "FUTURE_BENEFIT_CONDITIONAL"],
    "calculatedAt": "2026-10-16T02:00:00Z",
    "expiresAt": "2026-10-16T02:02:00Z"
  }
}
```
실제 응답에는 카드별 source/asOf, 현재 혜택 자격, appliedRuleIds, excludedReasons를 함께 제공한다. 계산 불능이면 recommendedCardId=null, status=HELD이며 확인 필요 항목을 반환한다.

## 동시성·계약 테스트
동일 Idempotency-Key+요청 해시는 같은 결과를 돌려주고 다른 body는409. 동기화 중복 접수는 같은 작업 참조. 예산/분류 수정은 optimistic lock. 추천 생성 시 스냅샷 버전이 맞아도 최신 원장/예산/규칙 버전으로 한 번에 읽고 basis 기록. 완료 직후 변경 감지 시 결과 무효화.
OpenAPI 문서는 이 표를 기반으로 구현 시작 시 파일화하고 Android DTO 계약 테스트를 수행한다. CON-03 인증 payload와 AUTH-01 공급자는 미정 항목으로 남겨 외부 호환성이 검증된 것으로 오해하지 않게 한다.
