# 다음 기능 구현 순서

확정 일정 없이 의존성 기준으로 진행한다. 코드 존재·실금융·실기기·운영 완료를 구분한다. 취소 원거래 미확정1건은 따로 보류하되 전체 기능 개발을 중단시키지 않는다. 별도 요청 없이 과거 월을 계속 조회하지 않는다.

1. 금융 카드와 실제 보유 상품 연결(FR03/04/10/15)
   - 현재 실제 거래는 가계부까지만 연결되며 수동 등록한 실제 카드와의 대응이 없다. 카드명·부분 마스킹만 보고 자동 확정하지 않는다.
   - 다음 구현 단위: 사용자가 조회 카드와 등록 상품을 확인해 연결/변경하는 API·Android 화면, 사용자 격리·충돌·이전 추천 무효화. 부분 번호 충돌·규칙 부족은 명확히 보류한다.
   - 이후 거래별 실적 제외/취소 접수월/혜택 조건을 검증해 실적·자격·추천에 연결. 미확인 값은0으로 만들지 않고 제한된 쇼핑 규칙을 모든 소비에 적용하지 않는다.
2. 실제 이용내역 분류(FR08/17)
   - 가맹점·사용자 정정에 기반한 분류 제안과 가맹점별 분류 기억·해제. 기존 OTHER 일괄 상태를 개선하고 예산에 반영. AI 없는 동작·수정 우선 보장.
3. 네이버플러스 스토어·무신사 결제 전 추천(FR11~15/19)
   - 기존 실험 감지 코드를 실제 주문 경로에서 확인하고 금액 변경·쿠폰·화면 이탈 시 추천 무효화 보완. 자동 클릭/카드 선택/결제 실행은 제외.
4. 서비스 운영 기능(FR01/02/21~24)
   - 이메일 확인/비밀번호 복구, 금융 추가 인증·UNKNOWN 대조, 외화 확인, 백업 복구/비밀 관리/오류 관찰. 유료 사용·공개 배포는 별도 결정.

검사는 각 변경의 금액·격리·취소·중복 위험에 맞춰 실행한다. 변경 없는 전체 검사와 기기 재설치를 반복하지 않는다. 현재 초기 추적표의 오래된 미구현 표시는 구현 증거와 대조해 정정했다.
