# 가상 카드 혜택 사용액·잔여 한도 연결 검증

2026-10-19 · 프로젝트 `C:\Users\SSAFY\Documents\card-advisor`.

## 구현 완료
- 수동 구매에 혜택 비율/규칙 버전을 저장하고, 연결 거래의 남은 카드 승인액으로 혜택 사용액·잔여 한도를 자동 재계산한다. 예산 지출액·포인트·머니와 구분한다.
- 건별 `floor((카드 승인액−카드 환불액)×비율bp/10000)`을 합산한 뒤 기준 한도 이내로 제한한다. 부분 취소는 원구매 월 전체를 재계산한다. 초과 소비가 남아 있으면 취소해도 잔여 한도가 복원되지 않을 수 있다.
- 현재 혜택 자격이 미충족이면 사용액0, 양수 거래의 자격·한도·환불액·규칙이 미확인이면 확정 금액을 만들지 않는다. 이번 달 실적 달성이 이번 자격을 승격하지 않는다.
- `baseRemainingCapWon`은 거래 차감 전 기준값, `remainingCapWon`은 거래 반영 후 값이다. 월별 입력 화면에서 계산값을 기준값으로 재저장할 수 있던 이중 차감 문제를 수정했다.
- 카드 재연결 시 순승인 혜택이 새 카드로 이동하며 비율/규칙도 갱신한다. 추천 조회는 사용액을 변경하지 않으며 실제 구매/취소/상태 변경은 기존 추천을 무효화한다.
- V5 거래별 혜택 규칙 보존, V6 기존 추천의 데이터 버전 무효화를 적용했다. 이전 마이그레이션과 거래/추천 기록은 보존했다.

DB의 원승인50,000원·카드환불20,000원·비율100bp·기준 한도10,000원으로 SQL에서 독립 재계산해 사용300원/잔여9,700원을 대조했다. 계산값은 별도 가변 누계로 저장하지 않는다. 각 실행의 합성 계정은 검증 후 삭제했다. 최초 화면 검사에서는 비동기 처리 종료보다 먼저 비활성 탭을 누르는 테스트 경합이 발생해 버튼 준비 대기를 추가했고, 수정 후 두 시나리오가 통과했다. 실패 실행의 합성 계정도 정확히 지정해 정리했다.

## 실행·사용
현재 백엔드 `127.0.0.1:18080`와 PostgreSQL `127.0.0.1:54329`를 실행 상태로 유지했다. 앱에서는 가입/로그인 → 설정의 가상 데이터 준비 → 카드 비교에서 구매금액 입력 → 가계부에서 카드 선택 → 구매 기록 추가/부분 취소로 확인한다.

프로젝트 루트에서 API 검사는 `python scripts/benefit_smoke.py`. 에뮬레이터 실행 후 `./scripts/android.ps1 ui-test`는 앱·검사 APK 빌드와 실제 화면/API/DB 확인을 수행한다. 월별 충돌 회귀는 `./scripts/android.ps1 monthly-test`. 자세한 API 계약은 docs/api/openapi.json.
