# 로그인 유지 및 안전한 토큰 복원

- 원인: ApiClient와 MainActivity가 토큰을 remember 메모리에만 두어 Activity/프로세스 종료·APK 교체 후 로그인 정보가 사라졌다.
- Android Keystore AES256/GCM 키로 액세스/리프레시 토큰만 암호화하여 noBackupFilesDir AtomicFile에 저장. nonce를 매번 생성하고 AAD로 슬롯을 묶는다. 비밀번호/이메일은 저장하지 않는다. Keystore와 파일 작업은 IO에서 실행하며 백업 대상 제외. 암호문 변조/키 무효화는 로그인 재요청으로 안전하게 처리. 근거 https://developer.android.com/privacy-and-security/keystore.
- 앱 시작 시 토큰 복원/로그인 화면 깜박임 방지, 동일 프로세스의 Activity들이 하나의 API 클라이언트를 사용. 복원과 갱신은 mutex로 직렬화. 인증 필터 SESSION_EXPIRED 응답에만 단일 리프레시 후 요청1회 재전송. 일반 로그인 실패/임의401/네트워크 오류를 재전송하지 않는다. 갱신을 서버가 처리한 뒤 Activity가 종료돼 결과 저장이 취소되지 않도록 해당 짧은 갱신 구간은 완료까지 보존한다.
- 네트워크 실패는 저장 세션을 유지. 서버의 리프레시 거절/폐기 시 메모리·파일을 비우고 로그인 화면으로 복귀. 로그아웃·계정 삭제도 파일 제거. 기존 서버1시간 access/30일 refresh 정책을 바꾸지 않는다.
- 에뮬레이터 실제 Spring/PostgreSQL 검사: 프로세스 종료 사이 토큰 복원, 암호문에 토큰/비밀번호 평문 없음, 동시3요청의 갱신1회, 재저장된 토큰 복원, 오프라인 보존, 로그아웃 삭제/변조 차단/서버폐기 삭제, Activity 재진입 자동로그인 및 UI로그아웃/재진입 로그인화면 확인 통과.
- SM-F741N은 실제 개인 세션 슬롯과 분리한 합성 슬롯/계정으로 프로세스 간 복원·단일갱신·오프라인·로그아웃·폐기4단계 통과. 개인 저장소는 테스트로 덮어쓰지 않았다. 합성계정은 모두 삭제. 실기기 UI 자동로그인 자체는 사용자 다음 로그인 후 확인할 범위이며, 에뮬레이터 UI 증거와 구분.
- 최초 UI 검사는 홈 화면에 로그아웃 버튼이 있다고 가정해 실패했다. 실제 설정 진입 후 로그아웃하도록 수정 후 통과. 복원 상태 전달 지연으로 정상 로그인이 풀리지 않도록 토큰 존재도 확인한다.
- 수정 APK 실기기 설치 완료. 기존 버전 메모리 세션을 추출/이전하지 않았으므로 이번 업데이트 후1회 직접 로그인 필요. 이후 암호화 저장을 사용한다.
- 근거 .run/session-emulator.log, session-physical.log, session-emulator-5554.json, session-R3CX701TE5J.json, session-final-build.log, session-real-state.json. 실제 카드번호·인증정보·토큰·파일 내용을 진단 출력하지 않음.
- 최종 금융전체회귀통과(.run/session-finance-regression.log): 상품연결/부분취소/중복보호/자동로그인복원/전체세션폐기 후 로그인버튼활성 포함. SM-F741N 최종 APK설치 및 일반앱/USB18080복원 완료. 실제 DB 상품등록1/금융매핑0/금융190/원장187/미연결취소1을 확인했으며 상품을 임의연결하지 않았다. 현재 개인 로그인은 이전메모리세션을 추출하지않아1회직접필요하다.
