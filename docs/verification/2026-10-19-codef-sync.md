# CODEF 승인·취소·할부 동기화 검증

검증일: 2026-10-19. 공급자는 로컬 합성 서버이며 실제 CODEF 인증정보·금융기관 호출을 사용하지 않았다. HTTP 인증과 사용자 격리, 트랜잭션 및 마이그레이션은 실제 Spring Boot/PostgreSQL로 검사했다. 이번 단계에서 Android 앱과 물리 기기는 검사하지 않았다.

## 구현
- 공식 KB(0301)·하나(0313) 승인 계약에 따라 `CodefApprovalNormalizer`와 `FinancialSyncService`/`FinancialSyncController`를 구현했다. 공식 출처·필드·API·제한은 [승인 정규화 계약](../integrations/CODEF-APPROVALS.md)에 기록했다.
- 사용자가 지정한 기간 동기화, 작업 조회, 정규화 거래 조회, 보류 거래 확인 API를 제공한다. 요청 키·연결 버전·사용자 소유권을 확인하고 응답 전체를 원자적으로 반영한다.
- 누적 취소는 증가한 차액만 반영한다. 별도 음수 취소는 원거래 확인 전 보류한다. 수동 구매 중복 후보는 확인 후 연결하거나 별도 구매로 기록한다.
- 할부는 승인 총액 한 번과 개월 수를 저장한다. 청구월 배분·수수료를 추정하지 않는다. 누락/외화/불명확한 취소는0으로 바꾸지 않는다.
- 보류된 금융 증거가 있으면 추천을 보류한다. 새 증거·변경은 사용자 데이터 버전을 올려 기존 추천을 무효화한다. 실제 카드 거래를 가상 혜택 규칙에 연결하지 않는다.
- V10에 동기화 작업/정규화 거래/환불 적용 이력을 추가했다. V11은 계정 삭제의 교차 참조 검사를 트랜잭션 종료로 연기한다. 기존 마이그레이션과 데이터 볼륨을 보존했다.

동기화 관련 합계68개는 실패0/오류0/건너뜀0이다. 기존 수동 API16개도 통과했다.

확인한 주요 경계:
- 같은 배치의 중복, 같은 요청 키 재조회, 겹치는 기간 재조회에서 구매/환불 중복 생성 없음. 내용이 같은 재조회는 추천 버전을 변경하지 않음.
- 50,000원 구매→누적20,000원 부분 취소→순지출30,000원. 같은 취소 재조회는 불변. 누적30,000원→순지출20,000원. 취소액 감소는 보류, 전체50,000원 취소→0원.
- 90,000원 3개월 할부는90,000원 구매 한 건. 외화·미확인 취소를 원화0 또는 확정 지출로 변환하지 않음.
- 별도 취소의 명시적 연결, 과다 환불·혼합 취소 방식 차단, 수동 중복 연결의 분류/예산 제외 보존, 별도 구매 확인.
- 동일 승인/요청 키의 사용자별 분리, 다른 사용자 자료404·미인증401, DB의 교차 사용자 외래키 차단.
- 동시 재요청은 기존 RUNNING을 반환하고 중복 외부 호출하지 않음. 조회 중 연결 버전 변경, 잘못된 응답, 같은 식별자의 상충 행은 전체 반영 중단.
- 새 보류 증거의 추천 무효화/신규 추천 보류. 이미 원장 반영한 불명확 거래를 IGNORE로 숨길 수 없음. 빈 조회 결과는 기존 거래를 삭제하지 않음.

## 발견 및 수정
1. 별도 취소가 적용된 후 그 행이 과다 환불로 보류되면, 누적 취소를 다시 적용할 수 있었다. 현재 상태가 아닌 영구 환불 적용 이력을 확인하도록 수정해 같은 환불의 이중 차감을 막았다.
2. 금융 거래·원장·작업의 교차 참조 때문에 계정 삭제의 cascade가 중간 상태에서 실패했다. V11의 지연 외래키로 트랜잭션 최종 무결성을 검사하도록 수정했다. 기존 V10 체크섬을 바꾸지 않았다.
3. 새 보류 증거의 데이터 버전 증가, 이미 반영된 거래의 IGNORE 제한, 한 응답 안의 모순된 중복 행에 대한 회귀 검사를 추가했다.

- 로컬 API `http://127.0.0.1:18080`, PostgreSQL `127.0.0.1:54329`. 새 JAR 반영 시 해당 프로젝트 서버만 재시작했다.

## 완료 경계
- 구현 완료: KB·하나 문서 범위의 백엔드 정규화/동기화/보류 확인 API.
- 로컬 검증 완료: 위 합성 계약·실제 HTTP/PostgreSQL 및 기존 수동 흐름.
- 실제 금융 연동 확인: 미완료. 계약/권한·추가 인증·실제 응답 확인 필요.
- 실제 기기 확인: 신규 동기화 기능은 미검증. 이전 금융 연결 관리 실기기 결과와 구분한다.
- 배포 준비/공개 배포/스토어 승인: 이번 범위에서 수행하지 않았다.
- 남은 구현: Android 기간 동기화/보류 확인 화면, 추가 인증, UNKNOWN 대조, 외화/기관별 청구 배분 및 실제 카드 규칙 연결.

공식 표에서 KB·하나는 부분 취소 구분을 보장하지 않는다. 수치가 제공된 합성 계약의 정확성 검증이며 실제 모든 부분 취소 수집 성공을 뜻하지 않는다. 공식 문서에 없는 페이지 토큰·호출 한도를 만들지 않았다.
