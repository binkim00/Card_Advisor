# Android 금융 거래 동기화 검증

2026-10-19. 실행 ID `987134bc-faa2-48f2-9383-a251e6a55014`. Android 16 에뮬레이터 `emulator-5554`의 실제 MainActivity → Spring API → PostgreSQL17.6을 사용했다. 금융 공급자는 로컬 합성 서버다. 인증정보·실제 CODEF 호출·물리 기기는 사용하지 않았다.

## 구현
- FinanceSyncEditor/FinanceSyncModels: 기간 입력·31일 범위/미래일 제한, 저장된 보류/전체 거래, 승인액·환불액·할부 개월·마스킹 카드·합성/공급자 출처 표시. 미확인은0으로 변환하지 않는다.
- FinanceEditor의 연결별 ‘기간별 거래·보류 확인’에서 진입한다. 활성 KB/하나 연결만 새 동기화 가능하며 UNKNOWN/해제/추가 인증/진행 중 상태에서는 보류한다. 저장된 결과 조회와 새 공급자 조회는 별도 버튼이다.
- 수동 구매 중복 후보의 날짜·금액·남은 지출·분류·예산 포함·연결 카드를 표시하고, 기존 구매 연결 또는 다른 구매 추가를 명시적으로 확인한다. 취소는 같은 카드의 반영된 승인 중 원거래를 선택한다. 선택만으로 저장하지 않는다.
- 금액 충돌·미확인 증거는 보류 이유를 표시한다. 아직 원장에 반영하지 않은 거래만 계산 제외 확인이 가능하며, 제외 지속/추천 재개 영향을 설명한다.
- 응답 전체를 검증한 뒤 화면에 반영한다. 조회 실패/잘못된 JSON/버전 충돌이면 변경을 막고 재조회한다. 버전 충돌 직후 선택과 기간은 보존하며 재조회 후 새로 확인한다. 화면 제거 뒤 취소된 작업은 상태를 갱신하지 않는다.
- 부모 화면의 추천·예산 캐시를 무효화하고 API 저장값을 재조회한다. 예산은 보류 거래 수와 확인된 지출임을 표시하며, 추천 보류/금융 거래 수동 취소 차단 오류를 한국어로 안내한다.
- 응답 유실/새 로그인 복구를 위해 `GET /v1/finance/connections/{id}/sync-runs`를 추가했다. 본인 연결의 최근20개 저장 작업만 읽고 외부 호출하지 않는다.

## 실제 앱·API·DB 검증
FinanceSyncFlowTest와 AndroidSyncPostgresTest의 통합 시나리오1개가 통과했다. 다음 경로를 한 흐름에서 확인했다.

1. 앱 회원가입·KB 합성 연결 생성, 저장 거래 최초 조회500 복구, 빈 목록, 잘못된 날짜 차단.
2. 합성 승인5건 수신: 수동 구매50,000/70,000원 중복 후보,90,000원 3개월 할부,20,000원 별도 취소, 환불 미확인30,000원. 보류4건·저장5건 확인.
3. 다른 세션에 의한 버전 변경 후409: 선택 보존·저장 차단·재조회·재선택.50,000원은 기존 구매와 연결하고70,000원은 별도 구매 추가.
4.20,000원 별도 취소를50,000원 원거래에 연결. 미확인 환불은 화면에서 ‘미확인’, 사용자가 계산 제외를 확인한 뒤 IGNORE 보존.
5. 같은 기간 재조회에도 중복 없음.90,000원 할부에 누적20,000원 취소 반영. 할부는 총액 한 번이며 월 청구액으로 나누지 않음.
6. 공급자 실패는 FAILED로 표시. DB 반영 후 응답 유실을 주입해 새 요청을 막고 저장된 작업 조회만으로 복구. 잘못된 조회 응답에도 저장 차단·재조회 복구.
7. RUNNING/UNKNOWN 신규 동기화 차단, 연결 화면 왕복, 새 Activity·재로그인 후 DB 재조회, 세션 만료 뒤 나가기.

최종 PostgreSQL 대조: 원장4건, 취소2건·합계40,000원, 예산 포함 순지출170,000원, 금융 거래5건·보류0·계산 제외1, 할부3개월, 수동 연결의 FOOD/예산 포함 보존. 공급자 호출은 연결1+명시적 동기화5=6회이며 응답 유실 후 추가 호출은 없었다. 동기화 작업5개 중 실패1개. 시험 계정 삭제 확인.

별도 FinancialSyncPostgresTest14개가 실패0/오류0/건너뜀0으로 통과했다. 신규 작업 목록의 인증/사용자 격리와 기존 정규화·중복·환불 계산을 회귀 검증했다.

## 발견·보완
- 결과 응답이 유실되면 앱에서 실행 ID를 알 수 없던 기존 API의 복구 공백을 연결별 작업 목록 조회로 보완했다. 반영 후 응답 유실을 실제 HTTP 경로에 주입해 재전송 없이 복구했다.
- 기존 예산/추천 오류 안내만으로는 금융 보류 원인을 알기 어려워 보류 수·금융 관리 안내를 추가했다.
- 처리 중 직전 완료 문구가 남지 않도록 새 작업 시작 시 ‘처리 중입니다.’로 바꾼다. 후보 분류 이름도 한국어로 표시한다.
- 검사 자체의 필수 카드 입력 누락, 이전 화면 메뉴 경로, 부분 문자열 비교 조건, 재로그인 조회 완료 전 탐색, 만료 세션 버튼의 비활성 기대 조건을 수정했다. 이를 제품 결함 수정으로 계산하지 않는다. 실패 실행도 해당 합성 계정을 정리했다.
- 실행2271aa3e의 취소 연결 뒤 완료 대기 실패1회는 원인을 확정하지 못했다. 개인정보 없는 고정 상태 분류/합성 DB 수치 진단을 추가한 뒤 실행2c1f8be1 전체가 통과했다. 최종 로딩 문구 보완과 인과관계는 미확정이며 영구 해결을 주장하지 않는다. 최종 APK의 결과는 위 실행 ID로 구분한다.
