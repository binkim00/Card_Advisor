# 2026-10-19 Android 파란색 UI 적용

## 구현
- 승인된 목업의 파란색/화이트 테마, 둥근 패널, 하단 홈·카드 비교·가계부·설정 탐색을 적용했다.
- 홈 예산은 기존 /v1/budgets/{month}/summary 결과를 표시한다. 미조회와 0원을 구분하고 고정비 제외 여유를 분리한다. 홈 조회 시 이전 추천을 무효화한다.
- 가상 카드 A/B의 계산 데이터와 실제 상품 안내 이미지는 구분한다. 실제 카드를 자동 등록하거나 가상 혜택을 실제 카드에 붙이지 않는다.
- 로그인, 결제 입력, 세 관점 비교, 구매·취소, 기존 월별 실적·예산·고정비·금융 편집은 그대로 연결되어 있다. 실물 상품 규칙 검수가 완료된 것은 아니다.
- 공식 상품 이미지 세 장은 원본 PNG 그대로 번들에 포함했다. KB국민 Easy all 티타늄 AUTO, 하나카드 트래블로그 스티커, 하나카드 트래블GO 티켓. 세 번째 카드가 하나카드라는 사용자 확인 반영.

## 충돌 방지
- work/blue-ui/android 별도 사본에서 빌드하고, dev.cardadvisor.android.designpreview 별도 패키지만 에뮬레이터에 설치했다.
- 테스트 채팅이 CODEF 백엔드 작업으로 이동했음을 읽기 전용 확인했다. MainActivity 원본 SHA-256 재확인 후 UI 파일만 반영했다. 기존 파일은 before-integration에 보관했다.
- backend, DB, API 프로세스, 휴대폰, 기존 dev.cardadvisor.android 설치 앱, 기존 Android 빌드 결과, 테스트 스크립트·Gradle 의존성은 변경하지 않았다.
- 원본 프로젝트에 designPreview 패키지 설정은 복사하지 않았다. 저장소는 Git 초기화 상태가 아니므로 작업트리/커밋을 만들지 않았다.

## 검증
- debug APK / unsigned release APK / instrumentation APK 빌드 통과. Release 서명·배포 준비·스토어 승인을 의미하지 않는다.
- 에뮬레이터 DesignUiTest 3개 통과: 로그인 입력/버튼 도달, 고정 탐색 및 busy 비활성화/복구, 예산 미조회가 0원으로 표시되지 않음.
- 화면 검사만을 위한 합성 구성의 스크린샷 2장을 확인했다. 실제 계정·전체 기기 화면·접근성 트리는 수집하지 않았다.
- 기존 API 요청식과 payload 13개가 동일함을 기계적으로 비교했다. ApiClient 및 기존 편집기 5개의 바이트가 동일함을 검증했다.
- 이번 변경 APK의 앱→실제 API→DB 회귀 및 물리 기기 검사는 수행하지 않았다. 이전 APK의 성공을 이번 디자인의 실기기 성공으로 간주하지 않는다.
- 증거/APK/화면: outputs/blue-ui-20261019. verification.json에 정확한 파일/해시 기록.

## 재현
- 프로젝트 JDK21/SDK35 환경에서 기존 Gradle 8.14.3으로 :app:assembleDebug :app:assembleDebugAndroidTest :app:assembleRelease 실행.
- DesignUiTest는 로그인 요청을 제출하지 않고 합성 화면만 검사한다. 기존 기기 검사와 동시에 같은 APK/기기에 설치하지 않는다.
- 에뮬레이터에서 `adb -s emulator-5554 shell am instrument -w -e class dev.cardadvisor.android.DesignUiTest dev.cardadvisor.android.test/androidx.test.runner.AndroidJUnitRunner` 실행 가능하다. 이 명령은 원본 패키지 APK 설치 후 사용하며 기존 테스트와 동시 실행하지 않는다.
