요청한 회원가입 → 가상 카드 준비 → 추천 → 수동 구매 → 부분 취소 흐름을 실제 Android 에뮬레이터에서 검증했습니다. 앱의 네트워크 계층과 서버·DB를 대체하지 않은 화면 통합 시나리오 1개가 통과했습니다.

## 발견한 문제와 수정
- 서버에 부분 취소 API가 있지만 앱에는 전액 취소만 있었습니다. 거래별 부분 취소 창과 금액 입력을 추가해 실제 API에 연결했습니다.
- 1원 미만·숫자 형식 오류·남은 지출 초과 금액은 앱에서 반영 버튼을 비활성화합니다. 50,001원 입력 차단과 20,000원 취소 성공을 화면 테스트로 확인했습니다.
- 가계부에 원래 금액, 누적 취소 금액, 남은 지출을 각각 표시합니다.
- 입력 제출 시 키보드를 닫아 결과와 오류 메시지를 볼 수 있게 했습니다. 숫자 변환 오류는 한국어 안내로 표시합니다.
- 이미 실적 기준을 채운 카드에도 이 구매가 실적 달성의 원인처럼 보이던 문구를 '구매 후 기준 충족 예상'으로 수정했습니다.

## 검증 환경과 결과
- Android 16 x86_64, emulator-5554. 물리 휴대폰 확인은 아닙니다.
- 수정 앱 APK 및 Android 테스트 APK 빌드 성공.
- 실제 Activity의 입력·버튼·스크롤을 Compose instrumentation 테스트로 실행했습니다. [Android 공식 테스트 문서](https://developer.android.com/develop/ui/compose/testing)를 기준으로 구성했습니다.
- 결과: OK (1 test), 14.513초.
- 백엔드 127.0.0.1:18080, 실제 PostgreSQL 17.6 사용. 가상 카드와 일회용 합성 계정만 사용했습니다.

| 단계 | 앱 확인 | DB 대조 |
|---|---|---|
| 회원가입 | 가입 완료 후 설정 화면 | 사용자 1명 |
| 가상 데이터 준비 | A/B 카드와 예산 생성 완료 | 카드 2개 |
| 50,000원 추천 | A 카드 혜택 1,500원, 구매 후 전체 예산 70,000원 | 추천 저장 |
| 수동 구매 | 남은 지출 50,000원 | 원거래 1건, 50,000원 |
| 추천 무효화 | 구매 기록 후 이전 추천 제거 | 기존 데이터 버전 무효화 로직 사용 |
| 초과 취소 입력 | 50,001원 반영 버튼 비활성화 | 취소 요청 전 차단 |
| 부분 취소 | 취소 20,000원, 남은 지출 30,000원 | 취소 1건 20,000원, 순지출 30,000원 |
| 추가 구매 추천 | 추가 50,000원 구매 시 전체 잔액 40,000원, 쇼핑 -10,000원, 고정비 고려 10,000원 및 초과 경고 | 최신 추천의 전체 잔액 40,000원 |
| 재로그인 | 새로고침 후 남은 지출 30,000원 유지 | 같은 원거래·취소 기록 유지 |

SQL은 테스트 실행 ID로 식별한 계정에만 조회를 제한했습니다. DB 대조가 통과한 뒤 해당 합성 계정 1명을 삭제하고 삭제 여부를 확인했습니다. 앱은 로그인 화면으로 다시 열었습니다. 기존 사용자 데이터와 다른 프로젝트 Docker 데이터는 변경하지 않았습니다.

## 재현 방법
백엔드·PostgreSQL과 emulator-5554가 실행 중인 상태에서 프로젝트 폴더의 PowerShell에서 다음을 실행합니다.

이 명령은 앱과 테스트 APK를 빌드하고 실제 API에 요청합니다. 성공 시 생성한 합성 계정을 자동 정리합니다. 실패 시 진단을 위해 해당 테스트 계정을 남기고 실행 ID를 표시합니다. 비밀키나 실제 금융 인증은 필요하지 않습니다.
