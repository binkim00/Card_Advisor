# 카드 어드바이저

한국어 Android 앱·Spring API·PostgreSQL로 카드 실적과 예산을 함께 보고 결제 전에 추천받는 서비스다. 기존 로그인 유지, 실제 금융 카드의 명시적 상품 연결, 승인 동기화/가계부/부분취소, 월별 실적·혜택 검토, 분할 예산/고정비 배분, 주문서 후보 확인, AI 실패 대체와 오프라인 조회를 구현했다.

**공개 서비스 완성 상태는 아니다.** 확인된 상품 규칙만 계산하며 미확인 실적·혜택·정산 조건은 보류한다. 이번 기기 없는 검사는 에뮬레이터와 합성 공급자 기준이다. 실제 쇼핑몰/기관별 인증·메일/AI 호출·운영 배포 경계는 [현재 상태](docs/STATE.md)와 [남은 범위](docs/SERVICE_GAPS.md)에 구분했다.

현재 로컬 API `http://127.0.0.1:18080`, 개인 DB `127.0.0.1:54329`, 격리 합성 DB `127.0.0.1:54330`. 준비된 환경에서 `./scripts/verify-device-free.ps1 -Emulator`로 전체 로컬 회귀를 실행한다. 결과는 `.run/device-free-verification.json`에 남는다. 이 명령은 개인 휴대폰을 사용하지 않는다.

디버그 APK는 `android/app/build/outputs/apk/debug/app-debug.apk`. release는 별도 서명과 운영 HTTPS 주소가 필요하다. 현재 APK를 빌드했다는 사실을 스토어 배포/승인으로 간주하지 않는다.

## 사용하는 흐름

가입/로그인 → 실제 상품 등록 또는 명시적인 가상 데이터 → 금융 연결/기간 조회 → 사용자가 금융 카드와 상품을 확인해 연결 → 거래·월별 실적/혜택 검토 → 비교 화면에서 결제조건 확인 → 추천 조회. 추천은 결제를 실행하거나 가계부에 구매를 자동 생성하지 않는다.

가계부의 분류 수정에서 예산 포함 여부·복수 카테고리 배분을 바꿀 수 있다. 가맹점 분류 기억은 다음 거래의 제안일 뿐, 기존 거래나 실적/혜택을 자동 수정하지 않는다. 반복 고정비는 거래 일부를 여러 일정·다른 납부 월에 나눠 연결할 수 있으며 구매월 지출과 중복 차감하지 않는다.

금액은 정수 원으로 결정적 계산한다. 이번 달 혜택 자격과 이번 소비로 채우는 다음 달 실적은 분리하며, null을 0으로 바꾸지 않는다. 알려진 값도 공식 조회/사용자 확인/자체 추정 출처를 구분한다. 인증정보·카드번호 원문·개인 화면·실제 거래 원문은 로그/저장소/AI에 보내지 않는다.
